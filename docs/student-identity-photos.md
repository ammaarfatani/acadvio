# Optional Student B-Form and profile photos

## Implementation

Student model now has optional `bFormNumber` (trimmed string, maximum 32 characters) and private `photoStorageId`. Existing `photoUrl` is retained for backward compatibility. No mandatory migration or alteration of existing records is required.

Student create/update APIs accept optional `bFormNumber` and `photoData` (JPEG/PNG/WebP data URL). Omitted fields preserve current values. `photoData: null` removes a photo. Client-selected paths/storage IDs and arbitrary new photo URLs are rejected. Existing legacy URLs are preserved when unrelated fields are edited.

The existing school/branch middleware and student create/update permissions apply. The authenticated `/api/student-media/:id/photo` endpoint checks student ownership; teachers additionally need an existing assignment, and parents need a linked child. It returns image data with private/no-store caching, using the existing bearer/refresh API client. No token is placed in the image URL.

The server reuses the existing bounded image decoder, then Sharp fully decodes, limits pixels, rejects animated/unsupported images, corrects orientation, reduces to a maximum 800x800 bounding box, and re-encodes WebP without original metadata. Unique GridFS keys are generated by the server. Bytes live in `studentPhotos.files` / `studentPhotos.chunks`, not ordinary student documents or ephemeral hosting disk. Existing persistent MongoDB storage is reused; no new external storage credentials are required. Backup/restore these GridFS collections alongside student records.

Photo replacements use a checked student update and delete the old file after success. Failed saves delete newly uploaded files where possible. Infrastructure failures during externally managed admission transactions can still require orphan-file cleanup; no unreferenced file is publicly retrievable. This is not a claim of a physical deployment/restore test.

## UI

- School Admin Students: create/edit B-Form, optional photo picker, preview, replacement/removal, disabled save while preparing/saving, existing avatar beside student name, B-Form column, profile history and admission print identity.
- Receptionist: enrollment form includes optional B-Form/photo, admission register uses enrolled student identity, student directory uses photos/fallback and B-Form.
- Teacher: assigned student directory and attendance roster use the shared circular avatar. Existing directory/detail permissions and class scope remain unchanged.
- Shared student history uses a prominent avatar and explicit missing B-Form label.
- Native select elements retain their existing text layout; photos are not invented for Excel rows or added to incompatible native dropdowns.

`StudentAvatar` provides initials and image-error fallback. Protected photos are lazily fetched for visible rows. `StudentPhotoField` accepts optional photos, resets the file input for replacement, shows local preview/preparation state and clear errors. Existing colors, tables, actions and scroll containers are retained.

## Imports and setup

Updated Excel/CSV template supports optional `B-Form Number` (also `Student B-Form Number` / `B-Form` headers). Format identification cells as **Text** to preserve leading zeros. Previously exported templates without this column continue to work. Imports do not fetch remote image URLs or embed image files; photos can be added using the student edit form after import.

Run the normal dependency install: Sharp is recorded in `package.json` and `pnpm-lock.yaml`. Restart the backend after updating source/dependencies. Configure optional `STUDENT_PHOTO_MAX_BYTES` (default 5242880, capped at 5 MB). Photo admissions use existing MongoDB transaction/replica-set support, consistent with parent-linked admission and fee workflows. No production `.env` was changed.
